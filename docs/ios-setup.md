# iOS Build — Setup & Release Guide

The `ios/` folder is a Capacitor 8 project generated with **Swift Package
Manager** (no CocoaPods needed). All 11 Capacitor plugins used by the app
have SPM support and are already wired into
`ios/App/CapApp-SPM/Package.swift` (that file is regenerated by
`npx cap sync ios` — never edit it by hand).

## What's already configured

- **Bundle ID:** `app.oceans-symphony.ios` (set in
  `ios/App/App.xcodeproj`). Apple forbids underscores in bundle IDs, so
  the Android id `app.oceans_symphony.twa` could not be reused. If you
  want a different id, change it in Xcode (Signing & Capabilities)
  **before** registering the app in App Store Connect — after the first
  upload it is permanent.
- **Versioning:** `MARKETING_VERSION` (the user-visible version) is set
  to match `APP_VERSION` (0.88.4 at scaffold time).
  `CURRENT_PROJECT_VERSION` (the build number, Apple's analogue of
  Android's `versionCode`) starts at 1 and must strictly increase per
  App Store Connect upload. **Release checklist:** the version triple in
  CLAUDE.md becomes a quadruple once iOS builds ship — bump
  `MARKETING_VERSION` alongside `appVersion.js` / `build.gradle`.
- **Info.plist:** location usage description (Location Records feature),
  `UIBackgroundModes` (fetch, processing, remote-notification), and
  `BGTaskSchedulerPermittedIdentifiers` containing
  `app.oceans_symphony.twa.friends` — this string must always match the
  `BackgroundRunner.label` in `capacitor.config.ts`.
- **AppDelegate.swift:** Background Runner task registration + APNs
  token forwarding for `@capacitor/push-notifications`.

## First build on the Mac

```bash
git clone https://github.com/penumbrias/oceans-symphony.git && cd oceans-symphony
npm ci
npm run build
npx cap sync ios
npx cap open ios      # opens Xcode
```

In Xcode:

1. Select the **App** target → **Signing & Capabilities** → check
   "Automatically manage signing" and pick your new Apple Developer
   team. Xcode registers the App ID for you.
2. Wait for SPM package resolution to finish (status bar top-right).
3. Pick a simulator or your plugged-in iPhone and press **Run**.

That should be enough for a working debug build. Everything below is
optional / later-stage.

## Push notifications (when you get to them)

1. Xcode → App target → Signing & Capabilities → **+ Capability** →
   **Push Notifications** (adds the `aps-environment` entitlement; the
   AppDelegate forwarding code is already in place).
2. Apple Developer portal → Keys → create an **APNs Auth Key** (.p8).
3. Firebase Console → Project Settings → Cloud Messaging → iOS app →
   upload the .p8 key with its Key ID and your Team ID. FCM then routes
   pushes through APNs — the existing server-side FCM code keeps
   working.

## Background friends-poll — expectations

`@capacitor/background-runner` on iOS uses `BGTaskScheduler`. Unlike
Android's WorkManager, **iOS decides when the task runs** based on usage
patterns — the 15-minute interval is a request, not a schedule. Tasks
also don't execute at all in the simulator. Test on a real device and
set tester expectations accordingly: friend-front notifications may be
delayed or batched when the app hasn't been opened recently.

## Things to verify on a real device before inviting testers

- **Storage persistence:** data lives in WKWebView's IndexedDB. Verify
  data survives app restart, device reboot, an app UPDATE (install a
  build, add data, install a newer build over it), and low-storage
  pressure. The origin is `https://app.local.oceans-symphony` (from
  `server.hostname` — Capacitor iOS uses the same hostname config;
  don't change `server.hostname` after shipping or every user's
  IndexedDB origin — and therefore their data — is orphaned).
- **Backup export/import:** the Filesystem-based export path and the
  file-picker import path both have iOS implementations, but the
  Downloads-folder conventions differ from Android — confirm the
  RecoveryScreen raw-backup path writes somewhere user-reachable
  (Files app).
- **Safe areas:** notch/Dynamic Island top inset and the home-indicator
  bottom inset, especially the configurable bottom-nav height and
  FloatingGroundingButton.
- **Local notifications:** reminder scheduling and the notification-id
  hashing (`nativeReminderScheduler` / `planReminderScheduler`) —
  behaviour should match Android but confirm delivery while the app is
  closed.

## App Store notes

- The privacy "nutrition label" is nearly empty: local-first, no
  account, no analytics. The only data leaving the device is the opt-in
  Friends feature and opt-in PluralKit / Simply Plural imports.
- Export-compliance question on upload: the app uses standard
  encryption (WebCrypto AES for at-rest encryption) — typically the
  "standard algorithms / exempt" answer path, but review Apple's
  current wording yourself before answering.
- TestFlight is the analogue of Play internal testing — testers install
  via an invite link, builds expire after 90 days.
- Xcode Cloud (included with the developer program) or a GitHub Actions
  macOS runner can automate builds later; the whole project builds from
  a clean clone with the four commands above.
